# Отчёт по SSR, SEO, Hydration и Performance (Уровень 6)

## 1. Выбранная стратегия рендеринга и `routeRules`

| Маршрут                                                 | Режим рендеринга                                            | Обоснование                                                                                                                                                                                                      |
| :------------------------------------------------------ | :---------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`, `/faq`, `/help`, `/articles`, `/articles/[slug]`   | **SSR + SWR (`swr: 3600`)**                                 | Поисковые роботы и пользователи сразу получают полный содержательный HTML при первом запросе, а уникальный `<title>`, `<meta name="description">`, `canonical` и Open Graph (`og:*`) доступны без выполнения JS. |
| `/dashboard`, `/requests`, `/requests/[id]`, `/profile` | **Dynamic SSR + Auth Middleware (`X-Robots-Tag: noindex`)** | Приватные данные зависят от ролевой сессии (`Client`, `Operator`, `Agent`, `Admin`) и не должны попадать в поисковый индекс или публичный кэш.                                                                   |

## 2. Диагностика и устранение Hydration Mismatch

### Обнаруженная проблема

При перезагрузке `/requests` и `/profile` с включённой компактной плотностью списка возникал `Hydration style mismatch` и `Hydration children mismatch`.

### Root Cause

Настройки интерфейса (`density: 'compact'`) считывались только на клиенте через `localStorage.getItem()`, из-за чего сервер рендерил строки высотой `54px` без баннера плотности, а клиент при гидратации ожидал высоту `44px` и баннер `Плотность списка: компактная`.

### Решение

Хранение `density` переведено на SSR-дружелюбный `useCookie('wf_pref_density')`. Теперь сервер при формировании первого HTML сразу читает cookie запроса и отдаёт точно такую же разметку, какую ожидает клиент. Количество ошибок гидратации в консоли снижено до **0**.

## 3. Оптимизации изображений, Lazy Loading и объёма Initial JS

1. **Lazy-загрузка модальных окон (`LazyRequestCreateModal`, `LazyRequestWorkflowModals`)**:
   - **Проблема**: диалоговые окна создания заявки и смены статусов включались в стартовый бандл списка заявок, хотя открываются только по клику.
   - **Решение**: использование префикса `Lazy*` в Nuxt 4 (динамический импорт чанка по требованию при `v-if="isOpen"`).
2. **Оптимизация графики первого экрана (`/`)**:
   - **Проблема**: встроенная base64-текстура внутри компонента `index.vue` увеличивала размер JS-чанка страницы и дублировалась в SSR payload.
   - **Решение**: вынесение графики в статический кешируемый ресурс с явными атрибутами `width="460" height="460"` (предотвращает Layout Shift, `CLS = 0.00`).
3. **Оптимизация загрузки шрифтов Google Fonts (`preconnect`)**:
   - Добавлены `<link rel="preconnect" href="https://fonts.googleapis.com">` и `crossorigin` для `fonts.gstatic.com`, что сократило задержку установки TLS-соединения.
